# 相对原始 SSD-TS Baseline 的改动全景文档

## 0. 文档目的

这份文档的目标不是简单列文件，而是把“原始 SSD-TS baseline -> 早期颜料迁移版 -> 当前增强版”的真实演化过程讲清楚。读完后，应该在**不看代码**的情况下，回答下面几个问题：

1. 原始 SSD-TS 做的是什么任务。
2. 当前项目相对 baseline 改了什么，为什么要改。
3. 哪些改动可以写成方法创新，哪些只是实验协议或工程支撑。
4. 当前项目从原始 RGB log / Raman / XRD 文件，到训练、推理、LUT 生成、可视化脚本的完整流程是什么。

本文档默认以**原始 SSD-TS**作为 baseline，而不是以任意一个早期 `pigment_task` 版本作为 baseline。

---

## 1. Baseline 定义：原始 SSD-TS 是什么

### 1.1 baseline 的原始任务

原始 SSD-TS 是一个**通用时序插补（time-series imputation）**框架。它的核心任务不是颜色恢复，也不是多模态颜料分析，而是在已有时间序列中对缺失值做扩散式补全。

从当前仓库保留的 upstream 代码可以看出这一点：

- `imputers/SSMImputer.py`
- `imputers/SISSMImputer.py`
- `ModelUtils/mamba.py`
- `config/config_bissm2_mujoco_90.json`

其中 `config/config_bissm2_mujoco_90.json` 明确展示了 baseline 的典型设置：

- 数据是通用时间序列，例如 MuJoCo；
- 输入维度是 `in_channels=14` 之类的时序特征；
- 目标是对随机缺失或规则缺失进行插补；
- 训练与推理都围绕“观测掩码 + 缺失位置生成”展开。

### 1.2 baseline 的核心模型资产

原始 SSD-TS 对当前项目仍有价值的核心资产主要是：

- diffusion 训练 / 采样范式；
- Mamba / SSM 风格的 denoiser 主体思想；
- 条件扩散的整体训练框架；
- mask-aware 的观测/缺失建模方式。

### 1.3 baseline 中不包含的内容

原始 SSD-TS baseline **不包含**当前颜料项目中的这些能力：

- 颜料褪色前颜色恢复任务定义；
- Raman / XRD 多模态输入；
- RGB-only missing-modality bridge；
- posterior / prototype bank / retrieval / gate；
- 面向 left/right、augmentation parent、spectral parent 的 split 协议；
- physics-informed soft constraints；
- LUT 生成与图像后处理脚本链。

因此，当前项目不是对 baseline 做“轻微调参”，而是在保留扩散主干思想的前提下，完成了一次**任务迁移 + 条件建模增强 + 工程化重组**。

## 2. 当前项目总目标

### 2.1 当前任务

当前项目的任务是：

- 输入：颜料褪色后的 RGB / Lab 颜色观测，或由 RGB log 形成的颜色对；
- 输出：预测褪色前的原始颜色。

当前实现仍保留了 diffusion + denoiser 主链，但任务语义已经从“时序缺失值插补”转变为“颜色恢复”。

### 2.2 当前训练期与推理期条件

当前项目采用的是：

- 训练期：可以使用真实 Raman / XRD 作为 teacher condition；
- 推理期：不能访问真实 Raman / XRD，只能使用 RGB；
- 因此推理阶段必须显式构造一条 RGB-only 的 pseudo spectral condition 路径。

这也是后续 bridge / posterior / prototype / retrieval 设计存在的根本原因。

---

## 3. 改动总览：相对 baseline 的四类主要变化

相对原始 SSD-TS，当前项目的改动可以分为四个大类。

### 3.1 任务迁移与数据重构

- 从通用时序插补迁移到颜料褪色颜色恢复；
- 用 pair-based 颜色样本替代原始通用时间序列段；
- 增加 Raman / XRD Excel 与 RGB log 的联合预处理；
- 通过 sidecar index 补足 parent/group/side 等运行时元信息。

### 3.2 多模态条件增强

- 新增 `models/spectral_encoder.py` 将 Raman / XRD 编码为条件空间；
- 新增 `models/color_encoder.py` + `models/cond_predictor.py`，让 RGB 分支学习预测谱条件；
- 保持 denoiser 主体不被推翻，只是增强其条件输入来源。

### 3.3 推理期缺失模态 bridge

- 将“训练有真谱、推理无真谱”的不一致，显式转化为 bridge 问题；
- 保留 `true / pred / retrieval` 历史路径；
- 进一步引入 posterior / prototype bank / gate / posterior_retrieval 联合路径；
- 使 Raman / XRD 的知识在推理阶段继续以 pseudo spectral condition 的形式生效。

### 3.4 physics-informed 软约束与推理稳定化

- 新增最小侵入式 physics-informed soft constraints；
- 新增单点推理稳定化、confidence 融合、Kalman/RTS 平滑；
- 新增高质量 LUT 生成链和 LUT 消费脚本。

## 4. 详细改动一：从 SSD-TS 到颜料任务的任务重定义

### baseline 做法

baseline 将样本视为通用时间序列，目标是恢复缺失位置的值。

### 当前做法

当前项目将样本重定义为：

- 一条颜色恢复样本由两个时刻构成；
- `x0[:, 1, :]` 对应当前观测颜色；
- `x0[:, 0, :]` 对应希望恢复的原始颜色；
- 模型学习在已知当前颜色的条件下，生成原始颜色。

实际实现位置：

- `data/parsing/preprocess.py`
- `data/dataset.py`
- `training/trainer.py`
- `inference/pipeline.py`

### 动机

真实数据并不是标准的长序列插补数据，而是围绕“褪色前/后颜色关系”组织的。直接沿用 baseline 的通用时序段定义，会让输入语义和目标语义不清晰。

### 对训练/推理流程的影响

- 训练和推理都转向 pair-based 颜色恢复；
- diffusion 仍然保留，但语义从“补缺失值”变为“在观测当前颜色时恢复原始颜色”。

### 限制与注意事项

必须明确：**当前真实实现仍然是 pair-only，不是完整 sequence 训练。**

这点与部分早期研究设想不一致，文档和论文中都应按真实实现表述。

## 5. 详细改动二：数据层、sidecar/index/split 改造

### baseline 做法

baseline 主要处理通用时间序列张量与 mask，不需要额外维护“增强来源”“谱 parent”“left/right”等元信息。

### 当前做法

当前项目新增了以下数据层能力：

1. **RGB log 解析与 pair 化**
   - 入口：`data/parsing/preprocess.py`
   - 将 RGB log 解析为 pair-based `x0`、`mask`、`meta_t`、`meta_patch_id` 等字段。

2. **Raman / XRD Excel 解析**
   - 支持 `meta_json` 映射；
   - 也支持单 `Sheet1` 宽表自动兜底；
   - 对真实实验文件更稳。

3. **sidecar index**
   - 入口：`data/index/sample_index.py`
   - 数据集消费：`data/dataset.py`
   - 记录 `side`、`sequence_parent_id`、`spectral_parent_id`、`augmentation_parent_id`、`split_group_id` 等信息。

4. **group-aware split**
   - 入口：`data/splits/grouping.py`
   - 训练侧采样：`training/samplers.py`
   - 让划分不再把 many-RGB-to-one-spectrum 的增强样本随机打散。

### 动机

当前数据存在以下现实约束：

- 原始序列数量很少；
- left/right 对照存在；
- RGB 扩增很多，但 Raman/XRD 没有同步大规模扩增；
- 不能把增强样本当成互相独立的原始样本。

因此必须通过 sidecar 和 group-aware 协议修正 baseline 的随机样本视角。

### 对训练/推理流程的影响

- 训练集 / 验证集 / 测试集划分不再只是随机索引；
- prototype bank 必须只使用 train fold；
- 某些正则项可以利用 parent/group 元信息，而不是只看单条样本。

### 限制与注意事项

- 仍然不改 NPZ schema；
- 新信息都放在 sidecar/runtime view 中；
- 某些 group 信息若缺失，相关功能会自动退化关闭。

## 6. 详细改动三：Raman / XRD 多模态条件接入

### baseline 做法

baseline 没有 Raman/XRD，也没有跨模态条件编码器。

### 当前做法

当前项目新增了显式多模态条件分支：

- `models/spectral_encoder.py`
- `models/color_encoder.py`
- `models/cond_predictor.py`

其中：

- `MultimodalConditioner` 将 Raman/XRD 编码为统一条件向量；
- `ColorEncoder` 将当前颜色编码为 `z_color`；
- `ColorToSpecPredictor` 让 RGB 分支预测谱 embedding。

训练时：

- 可以走真实谱条件；
- 也可以学习 RGB -> predicted spectral embedding。

### 动机

当前任务的关键不是简单看颜色，而是希望把谱知识引入颜色恢复过程。Raman/XRD 是训练期最强的外部先验来源。

### 对训练/推理流程的影响

- 训练阶段出现“true condition vs predicted condition”的双分支结构；
- 为后续 missing-modality bridge 奠定条件空间基础。

### 限制与注意事项

- 推理期不能访问真实谱；
- 因此这一步本身还不够，必须继续构造 RGB-only bridge。

---

## 7. 详细改动四：RGB-only missing-modality bridge

### baseline 做法

baseline 不存在“训练有一类模态、推理缺失该模态”的显式桥接问题。

### 当前做法

当前项目将缺失模态问题显式建模为 bridge，并统一到：

- `bridge/condition_builder.py`

当前真实支持的条件路径有：

- `true`
- `pred`
- `retrieval`
- `posterior`
- `posterior_retrieval`
- `auto`

其中：

- `true`：仅用于训练 teacher、上界、调试；
- `pred`：RGB 直接预测 spectral embedding；
- `retrieval`：RGB embedding 到库中检索谱 embedding；
- `posterior`：RGB 预测 prototype posterior，再聚合 prototype；
- `posterior_retrieval`：posterior 与 retrieval 联合，并通过 gate 融合；
- `auto`：根据当前 checkpoint 和配置选择稳妥路径。

### 动机

训练时有真谱、推理时无真谱，是当前任务最核心的结构性矛盾。bridge 的目标就是让谱知识在推理阶段不消失，而是转化为 pseudo spectral condition。

### 对训练/推理流程的影响

- 推理链从单纯 RGB -> denoiser，变成 RGB -> bridge -> pseudo spectral condition -> denoiser；
- 训练中出现 teacher cond、pred cond、posterior teacher 等额外监督。

### 限制与注意事项

- `true` 不能作为正式推理路径；
- 任何论文表述都不能写成“推理时访问真实 Raman/XRD”。

---

## 8. 详细改动五：posterior / prototype bank / confidence gate / retrieval 联合

### baseline 做法

baseline 没有 prototype bank，也没有 posterior 分布预测、confidence gate 或 retrieval 库。

### 当前做法

当前项目在 bridge 基础上继续增强，形成 GSPB 风格的链路：

- `bridge/posterior_head.py`
- `bridge/prototype_bank.py`
- `bridge/confidence_gate.py`
- `bridge/distill.py`
- `build_prototypes.py`

关键点如下。

#### 8.1 posterior head

让 RGB 不再只回归一个谱 embedding，而是预测一个 prototype 分布。

#### 8.2 prototype bank

从 train fold 的真实谱条件中聚合 prototype，形成局部记忆库。这样推理时可以从 posterior 分布聚合出 pseudo spectral condition。

#### 8.3 retrieval

保留基于颜色 embedding 的检索路径，既作为兼容路径，也作为 posterior 的对照和补充。

#### 8.4 confidence gate

在 `posterior_retrieval` 模式下，根据 posterior/retrieval 的置信度做融合，而不是写死只信某一路径。

#### 8.5 distillation

训练时用真实谱条件导出的 teacher 信息，约束 RGB 分支学习正确的 posterior 或条件空间。

### 动机

仅靠 `pred` 容易退化为单点回归，泛化不稳定；仅靠 `retrieval` 又容易受库分布和相似度偏差影响。posterior + prototype + retrieval + gate 的联合，提供了更稳的 missing-modality 推理链。

### 对训练/推理流程的影响

- 训练引入 posterior KL / distillation；
- 推理可以输出 posterior entropy、bridge confidence 等诊断量；
- `auto` 模式具备了比纯 `pred`/`retrieval` 更自然的默认路线。

### 限制与注意事项

- prototype bank 必须仅由 train fold 构建；
- 这是显式设计约束，不是可选实现细节。

---

## 9. 详细改动六：physics-informed soft constraints

### baseline 做法

baseline 没有面向颜色恢复问题的 physics-informed 正则。

### 当前做法

当前项目新增了两层物理相关设计：

1. 旧的 cycle-style 物理模块：
   - `models/physics.py`
   - 例如 `FadingForwardModelLab`

2. 新的最小侵入式 soft constraints：
   - `bridge/physics_heads.py`
   - `training/physics_losses.py`

新的 soft constraints 包括：

- Spec-Color Consistency；
- Parent / Augmentation Consistency；
- Damage Score Constraint。

### 动机

当前任务的目标不是建立完整物理世界模型，而是在不破坏主链的前提下，引入少量符合任务直觉的软约束，减少 bridge 漂移和不稳定颜色预测。

### 对训练/推理流程的影响

- 训练损失从单一主任务 loss 扩展为“主任务 + 可开关 physics regularizers”；
- 推理期不依赖真实 Raman/XRD，只可能多输出诊断量；
- 关闭 physics 后，旧行为尽量保持一致。

### 限制与注意事项

- 这些约束是 **soft constraints**，不是新的主模型；
- 缺少 group/order 信息时会自动退化为 0；
- 论文中可以写成增强设计，但不应夸大为完整物理建模框架。

## 10. 详细改动七：单点推理稳定化与 LUT 生成链改造

### baseline 做法

baseline 没有 LUT 生成，也没有面向单点 RGB 推理稳定化的后处理。

### 当前做法

#### 10.1 单点推理稳定化

`inference/pipeline.py` 新增了：

- confidence 融合；
- 低置信度回拉；
- `Kalman/RTS` 平滑；
- posterior entropy / bridge confidence / physics 诊断输出。

这让单点 RGB 推理结果更适合用于 palette 测试、LUT 构建和可视化。

#### 10.2 LUT 生成器

当前 LUT 构建脚本是：

- `pigment_task/build_pigment_lut33.py`

它经历了一个重要变化：

- 早期：每个网格点调用一次子进程推理，极慢；
- 当前：默认使用单进程批量 engine，一次加载 checkpoint，按 batch 推完整个 RGB 网格。

LUT 输出统一为：

- `grid`
- `lut_rgb`
- `lut_lab`
- `lut_conf`
- `lut_std`
- `lut_cdiff`
- `lut_cret`

### 动机

LUT 既是部署友好的推理缓存形式，也是后续图像脚本消费模型结果的关键中间件。没有稳定、统一、快速的 LUT 生成链，很多图像级实验都难以可靠复现。

### 对训练/推理流程的影响

- 模型推理结果被固化为三维颜色映射表；
- `t5.py`、`t6.py`、`t7.py` 等脚本直接消费 LUT，而不是重复跑模型。

### 限制与注意事项

- LUT 只是模型结果的离散缓存，不是独立模型；
- 提高 `grid_size` 和 `num_samples` 只会提升精细度/稳定性，不会改变方法本质。

## 12. 改动后的完整流程：从原始文件到论文实验

下面按真实执行顺序，重写当前项目的完整流程。

### 12.1 原始输入阶段

输入数据主要来自三类文件：

1. RGB log 文本
   - 左/右对照实验；
   - 按时间块记录多个 patch 的 RGB。

2. Raman Excel
   - 可能通过 `meta_json` 映射到 patch；
   - 也可能是单 `Sheet1` 宽表。

3. XRD Excel
   - 结构与 Raman 类似。

### 12.2 preprocess 阶段

主入口：

- `preprocess.py`

底层实现：

- `data/parsing/preprocess.py`

这个阶段完成的工作包括：

- 解析 RGB log；
- 按 patch 构造 pair-based 颜色样本；
- 把 RGB 转到 Lab 并归一化；
- 解析 Raman/XRD；
- 构建 `train.npz` / `val.npz` / `test.npz` / `all.npz`；
- 生成 `sample_index.csv` 和 split index；
- 记录 `preprocess_meta.json`。

### 12.3 dataset 阶段

主入口：

- `data/dataset.py`

它负责：

- 读取 `x0`、`mask`、`raman`、`xrd` 等 NPZ 字段；
- 兼容 `meta_t` 与历史字段；
- 挂载 sidecar 里的 `side` / `sequence_parent_id` / `spectral_parent_id` / `augmentation_parent_id` / `split_group_id`。

### 12.4 train 阶段

主入口：

- `train.py`

底层实现：

- `training/trainer.py`

训练时真实发生的主流程是：

1. 从 dataset 读取 `x0`、`mask`、光谱与 sidecar 信息。
2. `MultimodalConditioner` 对真实 Raman/XRD 编码，形成 true condition。
3. `ColorEncoder` 从当前颜色得到 `z_color`。
4. `ColorToSpecPredictor` 从 `z_color` 预测谱 embedding，形成 pred condition。
5. 若启用 posterior：
   - `PosteriorHead` 预测 prototype 分布；
   - 与 teacher posterior 做 KL 或 distillation；
   - 用 prototype bank 聚合 pseudo spectral condition。
6. denoiser 在条件扩散框架下预测恢复颜色。
7. 若启用 physics：
   - 再叠加 spec-color、parent/augmentation、damage 等 soft constraints。
8. 验证集监控、保存最优 checkpoint、早停。

### 12.5 prototype bank 阶段

主入口：

- `build_prototypes.py`

底层：

- `bridge/prototype_bank.py`

其作用是：

- 用 train fold 样本的真实谱条件聚合 prototype；
- 为 posterior 推理提供 prototype memory；
- 保证 bank 不泄漏验证/测试信息。

### 12.6 infer 阶段

主入口：

- `infer.py`

底层：

- `inference/pipeline.py`

推理时核心分流由 `cond_method` 决定：

- `true`：仅用于上界/调试；
- `pred`：RGB -> predicted spectral embedding；
- `retrieval`：RGB -> 检索库 embedding；
- `posterior`：RGB -> posterior -> prototype aggregation；
- `posterior_retrieval`：posterior + retrieval + gate；
- `auto`：自动选择当前 checkpoint 最稳妥的条件路径。

然后：

1. 组装 pseudo spectral condition；
2. 进入 diffusion 采样；
3. 输出原始颜色预测；
4. 计算不确定性、confidence、posterior entropy 等诊断量；
5. 若启用 `Kalman/RTS` 或单点稳定化，再做后处理。

### 12.7 LUT 阶段

主入口：

- `pigment_task/build_pigment_lut33.py`

当前默认流程：

1. 一次加载 checkpoint；
2. 构造 RGB 三维网格；
3. 按 batch 调用统一推理链；
4. 保存 `lut_rgb` / `lut_lab` / `lut_conf` / `lut_std` / `lut_cdiff` / `lut_cret`；
5. 支持断点续跑和 ETA。

### 12.8 实验脚本阶段

- `t1.py`：看模型对常见颜色的恢复趋势；
- `t2.py`：对整图聚类调色板做模型恢复；
- `t3.py`：模型直接生成掩膜区颜色先验图；
- `t4.py`：检查 NPZ/LUT 内容；
- `t5.py` / `t6.py` / `t7.py`：使用 LUT 驱动图像级应用与可视化。

## 13. 论文写作映射：哪些可以写成创新点

### 13.1 可以作为核心方法点

下面这些内容可以作为较强的方法创新来写。

1. **Raman/XRD 多模态显式接入颜色恢复**
   - 从 RGB-only 恢复扩展到训练期多模态 teacher。

2. **RGB-only missing-modality bridge**
   - 训练有真谱、推理无真谱；
   - 通过 pred / posterior / prototype / retrieval / gate 形成完整推理链。

3. **physics-informed soft constraints**
   - 在不推翻主链的前提下，为 bridge 和恢复结果增加一致性约束。

### 13.2 适合作为 supporting design / experimental protocol

下面这些更适合作为支撑设计或实验协议增强。

1. sidecar index 与 runtime metadata；
2. group-aware split 与 leakage guard；
3. prototype bank 只用 train fold；
4. posterior entropy / confidence 输出；
5. 单点稳定化与 Kalman/RTS 平滑。

### 13.3 不宜夸大为算法创新，但应说明

下面这些属于工程整理、可复现性增强或效率改进。

1. 自然命名入口与 wrapper/legacy 整理；

3. LUT 生成器从 subprocess 改为 batch engine；
4. `t1.py` 到 `t7.py` 的实验脚本收敛与兼容。
